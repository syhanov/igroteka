# Design Note M05: Перерисовка каталога при вводе

## Статус

Принято.

## Контекст

При поиске по каталогу необходимо обновлять отображение игр при вводе текста в поисковую строку.

Для этого можно полностью перерисовывать каталог через `innerHTML` после фильтрации массива игр или изменять уже существующие карточки, скрывая неподходящие и показывая подходящие.

Дополнительно при полном обновлении каталога можно использовать `debounce`, чтобы не выполнять фильтрацию после каждого символа во время быстрого ввода.

## Решение

Для поиска выбран полный `innerHTML` с использованием собственного `debounce`.

При вводе текста сначала выполняется фильтрация массива игр, после чего каталог полностью перерисовывается на основе найденных результатов.

`debounce` используется для того, чтобы не запускать фильтрацию и перерисовку после каждого введённого символа. Функция ожидает небольшую паузу в вводе пользователя и только после неё выполняет поиск.

Такой подход выбран потому, что он проще для текущего проекта и понятнее в реализации. Каталог строится из массива данных, поэтому при изменении поискового запроса проще заново получить подходящие игры и создать их карточки.

## Рассмотренная альтернатива

### Точечное скрытие и показ карточек

В качестве альтернативы можно было не перерисовывать каталог, а один раз создать все карточки и при поиске только скрывать неподходящие карточки и показывать подходящие.

В таком случае DOM-элементы карточек не уничтожаются и не создаются заново при каждом поиске.

Этот вариант был отклонён, поскольку для текущего проекта он сложнее и требует отдельно управлять состоянием каждой уже созданной карточки.

## Когда отклонённый вариант оказался бы лучше

Точечное скрытие и показ карточек был бы лучше при большом количестве уже созданных DOM-элементов и частом изменении фильтра, когда нежелательно постоянно удалять и создавать карточки заново.

Также такой подход был бы полезен, если бы карточки содержали состояние, которое необходимо сохранять при фильтрации.

## Последствия

### Положительные

- реализация поиска остаётся простой и понятной;
- источник данных остаётся массивом игр;
- каталог всегда строится заново из актуального результата фильтрации;
- `debounce` уменьшает количество лишних перерисовок при быстром вводе.

### Отрицательные

- при каждой фильтрации старые карточки удаляются и создаются заново;
- при очень большом количестве карточек полная перерисовка может быть менее эффективной, чем изменение уже существующих элементов;
- обработчики, установленные непосредственно на удалённых карточках, будут уничтожены вместе с ними.
